Meet the CoreS3 SE

ChipESP32-S3, dual core 240 MHz, Wi-Fi 2.4 GHz, BLE
Memory512 KB SRAM · 8 MB PSRAM · 16 MB flash
Screen2" 320×240 capacitive touch
AudioTwo microphones (ES7210) · speaker (AW88298)
Storagemicro SD slot
USBUSB-C, native USB on the S3: no driver needed

The SE leaves out

Camera, IMU, magnetometer, proximity sensor, battery. Everything today uses the screen, audio, SD and Wi-Fi, so the SE does it all.

Two shared buses

The SD card shares SPI with the screen. The mic and speaker share one I2S bus, so only one runs at a time.

The ecosystem

M5Stack

Controllers, plus Grove "Units" and stackable modules for sensors, relays, motors and more. Same software stack across the range.

M5Unified + M5GFX

One library for screen, touch, mic, speaker and power across M5 boards. M5.begin() and go.

PlatformIO

Board m5stack-cores3, Arduino framework. Same commands on Windows and Mac: pio run -t upload.

Claude Code

Writes, builds and fixes the firmware with you. It reads compiler errors and serial output, so keep them short.

Aims of the workshop

  • See what an AI coding agent can and cannot do on embedded hardware
  • Understand how a real LLM fits in 512 KB of RAM
  • Build a working device harness: UI, Wi-Fi, audio, storage
  • Connect the device to a cloud voice agent, and let the agent call back into the device
Try first, then fall back. Every step has a prompt you can give Claude and a reference implementation in the repo. Use them when you are stuck or short of time.

Pre-code checks

  • First boot. Power up the factory demo and run through it. Learn download mode: hold reset about 3 seconds until the green LED lights.
  • Critical SD card. Insert the card, check the demo shows it and its files. FAT32, 32 GB or smaller.
  • Repo. git clone to a short path: C:\dev\esp32-workshop or ~/dev/esp32-workshop. Not OneDrive or iCloud.
  • Environment. Run env/check-windows.ps1 or env/check-mac.sh, then pio run in env/hello-cores3.
  • ElevenLabs. Account, API key, agent ID. Copy secrets.example.h to secrets.h.
  • Critical Hotspot. Phone hotspot on 2.4 GHz, name and password in secrets.h. Check it with the Wi-Fi scan in Code 2.

Code 1

A 28.9M parameter LLM on your CoreS3

A story model trained on TinyStories, running entirely on the chip. No cloud. Folder code1-tinystories.

cd code1-tinystories
curl -L -o model/model.bin https://huggingface.co/slvDev/esp32-ai-tinystories/resolve/main/model.bin
# Windows: curl.exe -L -o model\model.bin (same URL)
pio run -t uploadmodel    # once per board, 15 MB, a minute or two
pio run -t upload
pio device monitor

Check for fp=a9bdd778 in the boot output: it confirms the model flashed correctly.

How 28.9M parameters fit in 512 KB

Put each part of the model where its read pattern belongs:

SRAM 512 KB
Activations and norm weights. Touched many times per token.
PSRAM 8 MB
Core layers and output head, int8. Read once per token. This is the speed limit.
Flash 16 MB
A 25M parameter embedding table. Only about 450 bytes read per token.

The trick is Google's Per-Layer Embeddings from Gemma 3n. Ask Claude: "Walk me through include/llm.h and explain where each tensor lives and why."

Code 2

Build the harness

Start an empty folder, open Claude Code there and build one feature at a time. Reference: code2-harness.

1 · Harness UI

Create a PlatformIO project for the M5Stack CoreS3 (board m5stack-cores3, Arduino framework, lib m5stack/M5Unified). Show a header bar and a home screen with four big touch buttons: WiFi, Record, Play, Chat. Chat is greyed out for now. Tapping a button opens that screen, each screen has a Back button. Use M5.Touch wasClicked() for taps. Add -I${PROJECT_DIR}/.. to build_flags so it can include secrets.h from the parent folder. Build it with pio run -s and fix any errors.

2 · Wi-Fi log in and out Critical

On the WiFi screen add Scan, Connect and Disconnect buttons. Scan lists up to 8 networks with channel and RSSI and highlights WIFI_SSID from secrets.h. Connect uses WIFI_SSID and WIFI_PASSWORD, times out after 15 s and explains the failure: network not found (probably 5 GHz), wrong password, or timeout (captive portal). Show IP and RSSI when connected, and a green or red dot in the header. Include secrets.h through a __has_include check with a clear #error if it is missing.

Voice record and play to SD

Add a Record screen: hold a big button to record 16 kHz mono from M5.Mic into a PSRAM buffer (max 30 s), show a level meter, and on release save a WAV file to /rec/recNNN.wav on the SD card. Add a Play screen listing the newest six recordings as buttons; tapping one plays it with M5.Speaker.playWav, tapping again stops it.
CoreS3 details: SD is on SPI with CS 4, SCK 36, MISO 35, MOSI 37, shared with the screen, so start M5 first, then SPI.begin and SD.begin(4, SPI, 25000000). The mic and speaker share one I2S bus: call M5.Speaker.end() before M5.Mic.begin(), and M5.Mic.end() before M5.Speaker.begin(). Keep the WAV buffer allocated until playback finishes.

Common problems

Silent recording, or the speaker stopsMic and speaker both started
"No SD card"Not FAT32, or not fully in. Reset after inserting.
Crash on playbackWAV buffer freed while playing
Code 3

Press to chat with an ElevenLabs agent

Connect WebSocket→ Hold: stream mic, base64 PCM→ Release: 1.2 s silence→ Collect audio events→ Play reply

Agent setup

  • Public agent: the device needs only the agent ID
  • Input and output audio: PCM 16000 Hz
  • Client tool show_message, string parameter text
  • Agent ID into secrets.h

Watch out

  • Audio messages can exceed 15 KB: common WebSocket libraries drop them
  • Answer every ping with a pong
  • Mic and speaker cannot run together
  • Hang up when done: minutes cost credits

Reference: the Chat screen in code2-harness. Prompts are in its README.
